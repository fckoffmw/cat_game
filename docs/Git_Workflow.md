# Git: как вносить изменения в проект

Инструкция для всех участников команды. Команды выполняются в **Терминале** (Mac) или в **Git Bash / PowerShell** (Windows) в папке проекта (там, где лежат `Assets`, `Packages`, `ProjectSettings`). Основная ветка — `main`, работаем в ней, свои ветки по желанию (раздел 8).

## 0. Словарь

| Слово | Что значит |
|---|---|
| Репозиторий | Папка проекта вместе с историей изменений |
| Коммит (commit) | Сохранённый снимок изменений с подписью. Хранится **только у вас на компьютере**, пока вы не сделали push |
| `push` | Отправить свои коммиты на GitHub, чтобы их увидели остальные |
| `pull` | Забрать с GitHub чужие коммиты в свою папку |
| `main` | Основная ветка, актуальная версия проекта |
| `.meta` | Служебный файл Unity рядом с каждым файлом в `Assets`. Без него Unity «теряет» файл, поэтому коммитим всегда вместе |

## 1. Один раз: подготовка

1. **Доступ к репозиторию.** Владелица репозитория (Катя) добавляет вас: GitHub → репозиторий → Settings → Collaborators → Add people. Примите приглашение, оно придёт на почту. Без этого `git push` не сработает (ошибка 403).
2. **Установите Git.** Проверьте: `git --version`. Если команды нет: Mac — установится вместе с Xcode Command Line Tools (macOS предложит сам), Windows — установщик с [git-scm.com](https://git-scm.com).
3. **Представьтесь Git** (имя и почта попадут в коммиты, почта лучше та же, что на GitHub):

   ```sh
   git config --global user.name "Ваше Имя"
   git config --global user.email "ваша-почта@example.com"
   git config --global pull.rebase false
   ```

   Третья команда задаёт обычное слияние при `git pull` и избавляет от ошибки `Need to specify how to reconcile divergent branches`.
4. **Клонируйте репозиторий** в удобную папку:

   ```sh
   git clone https://github.com/fckoffmw/cat_game
   cd cat_game
   ```
5. **Вход на GitHub.** При первом `push` Git попросит войти: в окне браузера (Windows — Git Credential Manager) или логин и **токен** вместо пароля (GitHub → Settings → Developer settings → Personal access tokens, право `repo`). Обычный пароль GitHub не принимает.
6. **Откройте проект в Unity 6000.3.10f1** (Unity Hub → Add → Add project from disk → папка `cat_game`). Первый импорт занимает несколько минут.

Если неудобно в командной строке, подойдёт программа **GitHub Desktop**: кнопки Fetch/Pull/Commit/Push делают то же самое.

## 2. Ежедневный цикл работы (главное)

Выполняйте по порядку. Рядом указано, что должно получиться.

### Шаг 1. Обновитесь перед началом работы

Сохраните сцену в Unity (Ctrl+S / Cmd+S) и желательно закройте Unity, затем:

```sh
git pull
```

Ожидаемо: `Already up to date.` (ничего нового) или список скачанных файлов. Если после `pull` у вас появились новые файлы, откройте проект в Unity, он их подхватит.

### Шаг 2. Работайте

Меняйте свою часть проекта в Unity. Сцену `Assets/Rooftop/VentRoof.unity` одновременно правит **один человек** (договоритесь в чате). Свою часть делайте в своих префабах.

### Шаг 3. Посмотрите, что изменилось

Сохраните всё в Unity (File → Save, Ctrl+S) и выполните:

```sh
git status
```

Вы увидите красным изменённые файлы. **Проверьте глазами**: должны быть только файлы, которые вы действительно меняли, и рядом с каждым `.prefab`, `.cs`, `.unity` и т. д. — его `.meta`. Папок `Library`, `UserSettings`, `Builds`, `Logs`, файлов `.DS_Store` в списке быть не должно (раздел 4).

### Шаг 4. Добавьте изменения в коммит

```sh
git add -A
```

Эта команда добавляет все изменения (включая новые файлы и удаления). Проверьте ещё раз:

```sh
git status
```

Теперь файлы зелёные, под заголовком `Changes to be committed`.

### Шаг 5. Сохраните коммит с понятной подписью

```sh
git commit -m "Добавить индикатор кулдауна прыжка"
```

Подпись — одна строка, **что сделано**, глаголом (примеры в разделе 3). Ожидаемо: `[main 1a2b3c4] Добавить индикатор…` и число изменённых файлов.

### Шаг 6. Обновитесь перед отправкой

```sh
git pull
```

Вдруг за время вашей работы кто-то уже отправил свои изменения. Исходы:

- `Already up to date.` — идите дальше.
- Скачались чужие изменения, всё прошло автоматически (может открыться окно с сообщением о слиянии, просто сохраните и закройте: в `vim` — `:wq` и Enter, в `nano` — Ctrl+O, Enter, Ctrl+X).
- Сообщение `CONFLICT` — раздел 6.

### Шаг 7. Отправьте на GitHub

```sh
git push
```

Ожидаемо: строки вида `main -> main` без слова `rejected`. Теперь изменения видны остальным: они делают свой `git pull`.

### Короткая версия цикла

```sh
git pull                              # забрать чужое
# ... работа, сохранить в Unity ...
git status                            # что изменилось
git add -A                            # добавить всё
git commit -m "Что сделано"           # сохранить
git pull                              # ещё раз забрать чужое
git push                              # отправить
```

Коммитьте **часто и понемногу** (раз в законченный кусок работы), а не раз в неделю огромным коммитом. Так проще искать ошибки и разбирать конфликты.

## 3. Как писать подписи коммитов

| Плохо | Хорошо |
|---|---|
| `fix` | `Исправить прыжок через воздуховод у края` |
| `изменения` | `Добавить таймер раунда на 60 секунд` |
| `финал 2` | `Подключить коробки к сдаче рыбки` |

Правило: прочитав подпись, другой человек понимает, что поменялось, не открывая файлы.

## 4. Что не коммитим

В `.gitignore` уже исключены `Library`, `Temp`, `Obj`, `Builds`, `Logs`, `UserSettings`, `.DS_Store` и служебные файлы IDE. Если эти папки всё же появились в `git status`:

1. **Не добавляйте их** (`git add -A` в таком случае не выполняйте).
2. Скажите в чате команде, проверьте, что вы в правильной папке проекта.

Секреты и пароли в репозиторий не кладём.

## 5. Файлы `.meta` и сцена

- Каждый файл в `Assets` имеет рядом одноимённый `.meta`. **Коммитьте их вместе**. Если закоммитить файл без `.meta`, у товарища Unity создаст другой `.meta`, и ссылки в префабах и сцене сломаются.
- Переименовывайте и перемещайте файлы **внутри Unity** (в окне Project), а не в Finder или Проводнике. Тогда `.meta` переедет вместе с файлом.
- Не правьте `.meta` руками и не удаляйте их по одному.
- Сцены (`.unity`) и префабы (`.prefab`) — текстовые файлы, но Git плохо объединяет изменения в них. Поэтому: **одну сцену правит один человек**, а перед открытием сцены делается `git pull`.

## 6. Если что-то пошло не так

### `git push` отклонён: `rejected … fetch first` или `non-fast-forward`

Это значит, что на GitHub уже есть чужие коммиты, которых нет у вас. Ничего не сломано:

```sh
git pull
git push
```

### `git pull` пишет `CONFLICT`

Конфликт возникает, когда два человека поменяли **одно и то же место** одного файла. Git не угадывает, чья правка нужнее, и просит выбрать.

1. Посмотрите, в каких файлах:

   ```sh
   git status
   ```

   Конфликтные файлы указаны как `both modified` под `Unmerged paths`.

2. **Текстовые файлы (`.cs`, `.md`).** Откройте файл. Увидите маркеры:

   ```text
   <<<<<<< HEAD
   ваш вариант
   =======
   вариант товарища
   >>>>>>> origin/main
   ```

   Оставьте нужное (можно объединить оба варианта), **удалите строки с `<<<<<<<`, `=======`, `>>>>>>>`**. Проверьте, что код собирается.

3. **Сцена и префабы (`.unity`, `.prefab`).** Руками их не правим. Выберите одну версию целиком:

   ```sh
   git checkout --ours путь/к/файлу      # оставить вашу версию
   git checkout --theirs путь/к/файлу    # взять версию товарища
   ```

   Потом договоритесь в чате, кто заново вносит потерянные правки в сцену.

4. Завершите слияние:

   ```sh
   git add путь/к/файлу
   git commit --no-edit
   git push
   ```

5. **Хотите отменить слияние** и вернуться к состоянию до `pull`: `git merge --abort`.

### `Need to specify how to reconcile divergent branches`

Git просит выбрать способ объединения. Выполните один раз `git config --global pull.rebase false` и повторите `git pull`.

### `Please tell me who you are`

Не заданы имя и почта: выполните два `git config --global …` из раздела 1.

### `Authentication failed` или `403`

Нет доступа или неверный токен. Проверьте, что вы приняли приглашение в Collaborators, и войдите заново (токен вместо пароля).

### `fatal: not a git repository`

Вы не в папке проекта. Перейдите в неё: `cd путь/к/cat_game`.

### Unity после `pull` показывает ошибки или сломанные ссылки

Закройте Unity, выполните `git status`, откройте проект снова. Если ошибка остаётся, напишите в чат, какой файл менялся последним.

## 7. Отмена изменений

| Ситуация | Команда | Замечание |
|---|---|---|
| Изменил файл, коммита ещё нет, хочу вернуть его как в последнем коммите | `git restore путь/к/файлу` | **Необратимо**: изменения в этом файле пропадут |
| Добавил файл в коммит командой `add`, но передумал | `git restore --staged путь/к/файлу` | Изменения в файле остаются |
| Сделал коммит, но ещё **не** делал `push`, хочу переписать | `git reset --soft HEAD~1` | Коммит отменится, изменения останутся в файлах |
| Уже сделал `push`, нужно отменить чужой или свой коммит | `git revert 1a2b3c4` затем `git push` | Создаёт новый коммит-отмену. История не переписывается |

Узнать хеш коммита: `git log --oneline -10`.

**Нельзя:** `git push --force` (затирает чужую работу на GitHub) и `git reset --hard` (стирает все ваши несохранённые изменения), пока не уверены, что понимаете последствия. Если хочется «починить всё одним махом» — сначала напишите в чат.

## 8. Своя ветка (по желанию)

Пользоваться ветками необязательно. Если хотите работать отдельно от `main`, например над большой задачей:

```sh
git switch main
git pull
git switch -c feature/arina-cat         # создать свою ветку от main и перейти в неё
# ... работа, git add -A, git commit -m "..." ...
git push -u origin HEAD                 # отправить ветку на GitHub (первый раз)
```

Дальше открывается Pull Request: на GitHub появится кнопка **Compare & pull request** (base: `main`, compare: ваша ветка). После проверки нажмите **Merge pull request** → **Create a merge commit**. Затем вернитесь в `main`:

```sh
git switch main
git pull
git branch -d feature/arina-cat         # удалить локальную ветку, она уже влита
```

Следующие `git push` из этой ветки делаются просто как `git push`.

## 9. Шпаргалка

| Что нужно | Команда |
|---|---|
| Что изменилось | `git status` |
| Что именно изменилось в файле | `git diff путь/к/файлу` |
| Последние коммиты | `git log --oneline -10` |
| Забрать чужое | `git pull` |
| Добавить всё в коммит | `git add -A` |
| Сохранить коммит | `git commit -m "Что сделано"` |
| Отправить на GitHub | `git push` |
| Текущая ветка | `git branch --show-current` |
| Перейти в `main` | `git switch main` |
| Новая ветка от текущей | `git switch -c feature/название` |
| Отменить слияние с конфликтом | `git merge --abort` |
