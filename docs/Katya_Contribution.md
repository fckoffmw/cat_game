# Работа Кати (Mac 2)

В проекте «Коты на крыше» Катя отвечает за ПР‑4 целиком, первую крышу и сетевые рыбки для ПР‑5. Реализация использует Unity 6000.3.10f1, Netcode for GameObjects и Unity Transport.

| Что сделано | Как проверено |
|---|---|
| Общая Unity-база и первая карта | Хост и клиент запущены в отдельных процессах macOS. На крыше есть парапеты, коробки, вентиляция с обходами и 12 рыбок. При повторном подключении второго игрока сервер выбирает свободную стартовую сторону. |
| ПР‑4. Серверное движение и прыжок | Клиент посылает пронумерованный ввод. Сервер проверяет направление, землю и кулдаун 3 с. Проверены столкновение с вентиляцией, прыжок через неё и приземление. |
| ПР‑4. Предсказание и коррекция | При задержке 100 мс в одну сторону без предсказания реакция в контрольном прогоне заняла 283 мс. С предсказанием подъём начался в том же шаге ввода. После намеренно раннего прыжка сервер отклонил команду, клиент исправил высоту и повторил 12 неподтверждённых шагов. |
| ПР‑5. Предметы | Подключена текстурированная модель рыбы. Сервер разрешает перенос одной рыбы, принимает сдачу один раз и через 5 с возвращает предмет. При одновременном касании рыбу получил один кот. Поздно вошедший клиент увидел 59 доступных рыбок из 60; после возрождения оба клиента увидели 60. |
| ПР‑5. Оптимизация Кати | На одной крыше размещены 6 секций по 10 сетевых рыбок. В двух прогонах с хостом, двумя клиентами и шестью сдачами за минуту переход от периодической полной рассылки к отправке изменений снизил исходящий трафик с 34,554 до 12,702 кБ/с (63,24%). |

При проверке рыбок в обоих режимах использовались два отдельных клиента и один хост на Mac. За 60 секунд посредники посчитали 2 073 273 байта исходящей UDP-нагрузки при полной рассылке и 762 129 байт при рассылке изменений. В эти числа входит также сетевой обмен движения. Сценарий при 175 мс и потерях 4% прошёл после подключения клиента. В отдельной попытке с потерями с первого пакета клиент не вошёл за 50 секунд.

## Как повторить проверки

1. На хосте оставьте 12 рыбок для ПР‑4. На отдельном клиенте перед подключением выберите «Предсказание своего кота». Чтобы увидеть разницу, повторите прыжок с выключенной галочкой.
2. Для задержки на одном Mac запустите из корня проекта `python3 Tools/udp_lab.py --port 7778 --server 7777 --delay 100 --loss 0`. Хост работает на 7777, клиент подключается к 127.0.0.1 на **7778**. Для второго профиля перезапустите посредник с `--delay 175 --loss 4`. Закрыть его можно через Ctrl+C.
3. В режиме предсказания прыгните, дождитесь приземления и нажмите **F8** до истечения трёх секунд (на Mac при необходимости **Fn+F8**). Это учебная ошибка локального прогноза. Сервер отклонит ранний прыжок, клиент вернётся на крышу. В консоли хоста появится REJECT.
4. Для ПР‑5 включите на хосте «60 рыбок». Галочка «полная рассылка» включает учебный исходный режим. Без неё изменения состояния рассылаются через NetworkVariable. Выбирайте режим до запуска хоста.
5. Для автоматической проверки соберите **Development Build** для macOS. В корне репозитория выполните команды ниже, подставив путь к исполняемому файлу сборки. Тест сам запускает и останавливает свои процессы, использует только localhost и записывает результаты в указанную папку.

```sh
python3 Tools/check_practice.py prediction Builds/Rooftop.app/Contents/MacOS/game_cats Builds/check-prediction
python3 Tools/check_practice.py fish Builds/Rooftop.app/Contents/MacOS/game_cats Builds/check-fish
```
